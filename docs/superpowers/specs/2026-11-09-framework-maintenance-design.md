# 节点与检索公共边界维护

基线：`ec23ae5`。本轮只修复两个已复现的问题，复用现有 Local／Temporal 执行权威和来源校验，不扩展编排、模型或存储能力。

1. Local 节点注册表未固定 `validate_output` 等公共端口，提交后替换方法可让非法输出绕过固定 Schema。沿用 Temporal 已有的六端口固定方式，在原 Local 配置／查询位置保存并核对入口；初始合法自定义保持可用，不把私有辅助方法纳入承诺。
2. VectorRetriever 的后续异步来源读取可跨过较早片段 TTL；公共 retrieve 和 KnowledgeContext.references 因而返回过期证据。复用 `_validate_expiry`，在直接向量结果和公共结果采纳边界核对最终选中项；不新增来源读取、自动刷新或重试。正常 Engine 后续 validate 已有保护，原复现不证明模型实际使用过期内容。

选择在现有公共边界加校验，避免新建注册表包装或再次读取所有来源；前者重复当前职责，后者增加远端调用且仍无法提供跨存储原子快照。来源替换／撤回继续由原 validate 协议复核。本轮只承诺当前边界的已知 TTL，不保证返回后的数据永久有效。

原 Action、审批、预算、效果回执与未知效果语义不变。派发后发现节点端口漂移不得重发处理器或撤销已确认回执；待恢复义务依原引擎处理。端口固定是本机对象与入口约束，不宣称递归保护任意内部函数／闭包／外部代码。

旧推荐制品、Alpha、全部历史失败及并行网站改动保留。冻结单独私有验证包，不替换推荐组合，不授予新的服务／模型／平台资格。完成验证后仅本地提交，单次跳过钩子，不推送或公开发布。
