# CLI 命令退出的关闭完成契约

日期：2026-10-29。维护基线 `199334d`；不增加功能、依赖、协议或执行权威，不改变原 a7／a8 制品和历史验收。

## 问题与最小修复

CLI `load_engine` 已检查工厂返回值的公共端口，并在校验失败时严格清理。校验通过后的正常命令却使用 `contextlib.closing`，只调用 `close()`，没有检查完成返回值。用真实 LocalEngine／SQLite Coordinator 加结构化代理复现：`close()` 返回 coroutine、generator、同步／异步上下文管理器或 `True` 时，命令返回 0 并输出已受理 Run，实际关闭逻辑未执行，原租约仍被占用；普通关闭异常则越过 CLI 的结构化错误边界。

私有 `_closing_engine` 复用已有 `ports.close_engine`，要求同步关闭返回 `None`。关闭失败统一保留 `RuntimeBuildError.cleanup` 原对象和异常原因，CLI 顶层仍按原 `RalfError` 规则脱敏并返回 2。框架不执行惰性清理，不把关闭失败当成业务回滚，不增加业务重试或取消。业务操作失败且关闭成功时保留原异常。

测试覆盖 submit-only 和完整离线执行，检查拒绝后原 Run／状态／租约仍在，关闭原执行者、修正工厂后以同一命令恢复原回执，不创建第二个 Run；另覆盖正常关闭、关闭失败句柄重试及原业务异常传播。
