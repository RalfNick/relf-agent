# Framework 接入边界维护设计

基线：`e317a48`。用户授权继续对比并优化框架；沿既有执行权威、恢复和不推送／不公开发布的约束实施。

本轮对照 AgentScope 与 LangChain／LangGraph，优先解决已有能力的实际接入失败，不增加循环、流式 Workflow、多模态或执行后端。

## 已确认的问题

1. Node input/config Schema 被嵌入 Tool 包装后，本地 `$defs/$ref` 引用根改变。
2. 多个公共数据校验入口使用 jsonschema 默认引用检索，未固定文件／网络内容可改变相同发布的校验结果。
3. Embedding HTTP 的递归解析和已关闭借用客户端错误没有转换为脱敏 ProviderError。
4. 资料助手 slash 命令引号不完整时，shlex 的 ValueError 退出整个聊天。

## 实现取舍

- Schema 复用项目已有的无外部检索 Registry，统一有限公共输入／输出采纳边界的错误，不新增解析服务或可变全局资源缓存。固定 Schema 内的引用仍可用；外部未固定资源明确拒绝。
- 节点仅在需要独立引用根时为嵌入副本增加确定性资源 ID；保留用户原 Spec、已有有效 ID 和无引用节点 Manifest。不会盲目重写所有字符串或 `$ref`。
- 不引入外部 Schema 自动下载方案；它需要新的来源固定和发布契约，与本轮维护范围不符。
- Embedding 保留取消传播、单次请求和 owned/borrowed 生命周期；只规范已确认的异常类别。
- 聊天仅转换 shlex 解析失败，继续使用原错误呈现与执行入口，不吞掉业务代码的普通异常。

## 验收与边界

先保存针对真实入口的 RED，再最小修复、定向回归和目录外安装验证。节点须验证本地引用、独立 config、非法输入提前拒绝、原审批／重开及重复命令不重写；原记录、原制品、原期限保持。完整离线回归的结果按本轮实际运行记录，不替代真实模型、Service、平台或外部采用资格。

对比结论另以官方页面和本地支持矩阵记录，避免把其他平台服务全部计入 SDK，或用测试数推断任务质量／可靠性胜负。
