# 框架整体审查（2026-10-30）

审查基线：本地 `11fa206`；开始时工作区干净。本次检查当前代码、接口、阶段矩阵、安装制品记录、真实质量与性能报告，并执行针对性回归和边界复现。没有修改产品代码，没有启动远端 CI、发布、真实模型或外部服务验证。

## 结论

Relf-Agent 已具备可靠应用型 Agent SDK 的 Alpha 基础。单 Agent、Session、语义 RAG、有限 Plan／Team、审批、效果核验与原运行恢复有实现和相应证据；近期也交付了高层事件订阅、显式模型／异步工具增量、连续应用教程和 Local 无模型 Tool 图配置。

主干架构值得保留：Harness 提案与执行分离，Local／Temporal 各自持有执行权威，Session／Facts／Knowledge 与执行事实分离，效果回执与处理器实际结束分别核验。当前更需要收敛交付和降低接入成本，而不是增加新的执行内核或全面重写。

本次抽查没有发现要求推翻架构的证据；这不是对整个 SDK 的无缺陷保证。完整 R01–R26、通用图计算、企业生产治理、外部独立采用与框架对等质量仍未闭环。

### P3：公共时间参数的异常边界不完整

位置：[agent_runtime.seconds](../../src/relf_agent/agent_runtime.py)，影响 Runtime 构造、等待以及关闭覆盖参数等共享调用点。

`math.isfinite(value)` 对 `10**400` 这样的 Python 整数会抛出 `OverflowError`，因此无法进入预期的 `ValidationError` 分支。使用真实 LocalEngine 分别调用以下入口，均已复现 `OverflowError`：

```python
Runtime(engine, close_timeout=10**400)
await handle.wait(wait_timeout=10**400)
```

影响限于异常输入的错误契约，不是正常任务失败、数据丢失或重复业务效果的证据。建议统一拒绝无法表示为有限秒数的数值，并针对共享帮助函数与公共入口补充回归。

## 能力与设计判断

| 方向 | 当前判断 | 必须保留的边界 |
| --- | --- | --- |
| Agent／Runtime／Session | 高层入口、资源所有权、异步托管、控制与恢复已形成链路 | 普通 Agent 需要明确模型；不同执行后端不是可任意热切换的同一权威 |
| 工具与效果协议 | Schema、显式效果类别、审批、原 Action／effect key、未知效果核验设计合理 | 回执、预算结算和实际处理器结束继续分别验证；执行 credits 不是真实费用 |
| 事件与展示流 | 持久游标、高层订阅、文本／工具增量和结束事实已交付 | 展示增量不采纳决策或确认效果；不是逐记录流式 Workflow |
| Workflow／Plan／Team | 静态图、有限并行、计划与团队执行有实现；Local async Tool 可直接配置 | 通用异步节点、类型化共享状态／reducer、循环及流式数据背压仍未形成完整能力 |
| 记忆／RAG／数据 | Session／Facts 分层、语义检索、来源回读与替换端口有基础 | 冲突／遗忘、删除传播、索引修复、产物 GC、大规模数据质量仍开放 |
| Temporal／服务治理 | 已选择的恢复、审批、故障和生命周期组合有真实服务证据 | 新增流的真实证据主要是原生文本 Agent；高级组合、在途 Activity 故障及真实业务写不能自动继承 |
| 模型与生态 | 多种文本协议和显式 Provider／Tool／存储替换入口可用 | 多模态、更多真实型号、完整 MCP 会话／OAuth、业务连接器与企业 OIDC／ACL／HA 仍不足 |

[Harness 契约](../../src/relf_agent/harness.py)明确禁止模型／工具调用、Action ID 生成和状态提交；[工具回执接收](../../src/relf_agent/engine.py)与后续采纳分开。这些分工直接服务恢复正确性，应继续保持。

组件可替换的基础较好，但不能把部分端口和适配器的替换资格推导为任意高级编排可互换。业务定制目前最清晰的入口是 Provider、Tool、Profile 与参考应用；复杂业务状态与通用节点仍需明确需求驱动。

## 维护成本

本次统计产品源码为 **448 个 Python 模块、133,431 物理行**，含空行和注释，不含测试／文档。LocalEngine 2,892 行，Temporal Activities 2,220 行，主 Workflow 2,118 行，状态模块 2,034 行。

规模已经值得认真控制，但不能只凭代码行数判定过度设计。实际风险在于 Local／Temporal 的重复规则、分散的生命周期／身份校验、组合资格及旧运行兼容成本。建议只在具体缺陷或可复现重复逻辑推动下提取共享纯规则，后端继续各自推进状态；大范围内核重构会增加恢复验证负担。

建议把下一批固定为“同一候选的交付一致性与首次接入验收”：

4. 达到上述门槛即冻结。通用节点／reducer、数据生命周期、多模态、更多 Temporal 组合与企业治理继续列在长期清单，由实际用户需求选择下一项。
